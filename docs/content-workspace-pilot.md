## 启动

在博客根目录的 PowerShell 中：

```powershell
$env:CONTENT_WORKSPACE_DIR = 'D:/projects/folio'
pnpm dev
```

若端口被其他开发进程占用，使用 `pnpm dev --port 3107`，预览地址相应替换端口。环境变量只作用于这次终端启动的进程；也可自行在本机被忽略的 `.env` 中设置同名值。不要把真实工作区复制到 public 或提交进博客仓库。

首次在另一台机器建立新的空目录时：

```powershell
pnpm content:workspace init --workspace D:/writing/koto-pilot --source docs/drafts/characters-from-a-character-card.cn.md
pnpm content:workspace status --workspace D:/writing/koto-pilot
```

init 拒绝覆盖非空目录。新建的工作区只有原稿导入版，不自动生成演示修改或评论。

## 平时怎么用

1. 打开预览，“正文”显示所选的已记录版本，保留 Koto 一作、parz1 二作。
2. 在“源稿”编辑当前工作副本，填写修改说明，点击“记录新版本”。这始终编辑当前工作副本，顶部选择旧版不会让它覆盖成旧版。
3. 在“修改对照”选择起点，与顶部选中的目标版本比较。正文展示逐行增删，元数据变化另列；旧版和新版都有行号与增删符号。
4. 在正文中选中一句话，再点击该段“评论”；也可以直接填写该段里唯一出现的原文引用。保存后，线程固定到那一版原文。
5. 在讨论中回复、解决或重新打开。点击引用定位原段落；原文改变或匹配不唯一时保留引用，并提供“查看评论原版本”。

“本次操作的署名身份”用于记录当前人选择的公开身份，不是角色加载或身份认证。浏览器手动操作标记 human；脚本操作标记 agent；导入标记 import。不调用 characters，也不向任何角色记忆写入内容。

用 Obsidian 或编辑器直接改外部正文后，点击“刷新工作区”。工作台会提示未记录修改；打开源稿后记录新版本。也可以从 CLI 记录磁盘文件：

```powershell
pnpm content:workspace checkpoint --workspace D:/projects/folio --summary '补充项目起因'
```

CLI 的记录者为工具，浏览器再刷新即可看到。每次刷新会重新载入磁盘文件；不要用它来保留尚未提交的浏览器编辑。其他操作失败不会自动清空源稿。修改基线或磁盘摘要不匹配时返回 409，不覆盖已经发生的外部编辑。

## 存储和边界

工作副本是普通 Markdown，保留原始字节。`.workspace/state.json` 保存完整修订快照、稳定段落 ID、评论与解决事件；`workspace.json` 保存工作区身份。单个试点的完整元数据使用一个状态文件，原子替换避免出现半份状态；写入锁防止并发覆盖，已退出进程的锁可在后续写入时恢复。临时文件不作为有效状态读取。

先写工作副本、后提交修订状态；中途退出时，工作副本可能显示为未记录修改，但上一版完整快照仍保留。重新打开后检查并记录即可。普通编辑器不参与写入锁，应避免与浏览器在同一瞬间并行写同一文件；摘要检查能识别已发生的修改，但不能为不参与协议的编辑器提供文件级比较交换事务。这不是多人数据库，不提供多机事务、自动三方合并或断电级持久性保证。损坏状态或无法识别的锁应先备份并检查，不自动删除数据。

备份整个外部工作区，不能只复制 Markdown。工作区不包含博客代码，也不包含角色私人记忆。当前一份工作区只管理这篇草稿的一个语言版本；切换语言需要独立变体，试点会拒绝在同一变体中改语言。

评论定位优先使用未变段落的稳定 ID，再以原文与前后文查找唯一候选；段落重复、文字删除时不猜测新位置。偏移按 Unicode code point 记录。评论和所有修订都保持私有，没有“公开”开关。

预览页及 API 在生产环境返回 404；本地 API 检查 loopback Host 与连接地址，写入另校验同源 Origin。响应禁用缓存，页面标记 noindex。工作区路径只能由服务端环境变量指定，请求不能选择任意磁盘路径。

## 当前限制与下一步

- 正文采用安全的简化预览：段落、标题和代码文本，不执行 HTML、MDC 或 Vue 组件，也暂不还原 Markdown 的全部行内排版。Koto 草稿的文字结构可读，复杂内容的现有完整渲染器接入留待后续。
- diff 是逐行统一对照，不做词级高亮、左右分栏或自动语义解释。
- 评论支持原文引用、回复、解决、原版本定位；暂未做手动重定位和复杂 Markdown 的文本映射。
- 预览为手动刷新，不监视任意外部目录。所有修订一次读入，仅适合单篇试点，后续再做按版本加载与分页。
- 不支持发布包、线上访客评论、共享预览、同步、开放网络写入或多语言工作区 UI 之外的稿件变体管理。

测试命令：`pnpm test:workspace` 与 `pnpm test:authors`。重点覆盖完整快照、并发与外部编辑冲突、评论重复／删除定位、回复与解决、退出进程遗留锁的恢复、生产和跨来源访问拒绝。
