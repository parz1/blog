# Cloudflare 免费层动态功能验证：2026-10-30

结论：当前版本不适合将全部动态功能迁入免费 Workers。预渲染的博客内容可以继续试用，动态 SSR 尚未达到正式切换条件。正式域名、Vercel 和账户套餐均未修改。

## 测试方法

只访问测试站 `parz1-blog-preview.parz1zhou.workers.dev`，使用隔离 D1 `blog-preview-content`。脚本 `scripts/audit-cloudflare-dynamic.mjs` 覆盖 88 个请求案例：三种语言的全部 21 个 demo 路由、tech、概念局部图谱、旧作者重定向、7 个公开集合查询，以及阅读计数的禁用状态、跨站拒绝、无效文章、本地接口和不存在页面。

每次运行三遍，第一遍串行，后两遍并发度为 3。进行了 baseline、diagnostic、cold-api 三次有限运行，共 792 次请求，不是持续压测或长期监控。每次请求都有状态记录，集合查询还检查 JSON 数据；HTTP 200 的实验页入口不等于整个浏览器功能已通过。

cold-api 运行前上传并切换了一个仅增加测试标记的版本 `be029300-5a13-4ae9-b562-5c067ac1dca1`，先请求内容查询再请求页面。它验证了新版本激活后的请求，不代表清空 D1、每个请求都强制新 isolate，或覆盖全球节点。

同时订阅 Wrangler Tail，仅保留路径、方法、状态、CPU、wall time、outcome 和有限错误信息，不保存 IP、请求头或地理位置。收到的 invocation 事件并不覆盖全部请求，不能用日志样本比例推断线上错误率。

## 实测结果

| 运行       | HTTP 请求 | 不符合预期 | HTTP 1102 | 集合查询成功 |
| ---------- | --------: | ---------: | --------: | -----------: |
| baseline   |       264 |        115 |         2 |        21/21 |
| diagnostic |       264 |        103 |         4 |        21/21 |
| cold-api   |       264 |         44 |         5 |        21/21 |

“预期”包括特意测试的拒绝状态；例如无 GitHub 凭据的 500 是预期禁用行为，绝不是 GitHub 功能可用。这个表也是特定案例和测试顺序的结果，不是正式访问故障率估计。

| 功能                                    | 结论和边界                                                                                                                                                                                     |
| --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 未预渲染 SSR 页面                       | 不稳定，真实出现 HTTP 503 / Cloudflare 1102。diagnostic 日志取得 `exceededCpu`、CPU 10ms 的事件；成功 SSR 样本也有几十到数百 ms CPU，不能依赖偶发放行。                                        |
| i18n / 错误渲染                         | diagnostic 99 次、cold-api 39 次返回 `Cannot redefine property: $i18n` 的 500，涉及页面、重定向及部分不存在路由。与 CPU 失败同时出现，但未证明因果关系，不能宣称升级套餐就能解决。             |

## 测试后的部署状态

已将测试站流量恢复到原先的预渲染版本 `8f8f5a7c-f6b9-41c8-92fc-29618c3e2559`，测试标记不再生效。恢复后复查的 13 个公开静态入口全部成功，但 `/api/__local/content-workspace` 当次返回 i18n 500 而非预期 404，所以完整 smoke 仍未通过。此前一轮单次 smoke 成功不能代表持续稳定。

原始有限测试记录保存在忽略的 `.local/cloudflare-dynamic-{baseline,diagnostic,cold-api}.json`，汇总在 `.local/cloudflare-dynamic-summary.json`。脚本遇到不符合预期的响应会退出失败，复跑可能消耗少量测试站请求与 D1 配额。

## 下一步的取舍

如果坚持免费：将剩余 demo 外壳、tech 和按 slug 生成的图谱页一并预渲染；旧地址在路由层直接重定向；未知页面和本地 API 在 Worker 入口直接拒绝，避免启动整套 Nuxt 错误渲染。浏览器端 Python、WebGL、LUT 仍可保持交互。内容已经是固定发布包，读接口也可以评估进一步静态化。

如果保留广泛 SSR：另行评估 Workers Paid，但付费只放宽 CPU，仍需要单独解决并复测 i18n 错误。GitHub 和真实阅读计数需要独立测试凭据与隔离存储后才能完成验证。

本次只添加验证脚本和记录，没有调整 SSR 策略、替换依赖或升级套餐。下一轮修改应以消除上述故障并重复有限验证为验收条件。

官方依据：[Workers CPU 限额与 isolate 弹性](https://developers.cloudflare.com/workers/platform/limits/#cpu-time)。Free 单次 HTTP CPU 配额为 10ms，偶发超过可能放行，持续超过会终止；网络等待时间不计入 CPU。成功请求超过 10ms 不等于免费配额已经提高。
